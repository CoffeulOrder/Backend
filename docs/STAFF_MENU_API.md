# 사장님 품절 관리 API — MS-12·13·14

고객 메뉴 조회·주문 검증이 읽는 기존 `is_sold_out` 값을 변경한다. 새 DB 마이그레이션이나 PG 설정은 필요하지 않다.
코드 반영·배포 여부는 해당 PR과 개발 서버에서 별도로 확인한다.

## 권한

- 활성 `STAFF` 계정으로 로그인한 `OWNER`·`STAFF`만 사용한다. CUSTOMER·ADMIN·다른 주체의 토큰은 403이다.
- 계정의 현재 활성 상태·역할·사업자가 토큰과 일치해야 한다. 정지되거나 역할/소속이 바뀐 계정의 이전 토큰은 사용할 수 없다.
- OWNER는 같은 사업자의 매장, STAFF는 배정된 매장만 접근한다. 매장 영업 상태와 무관하게 관리할 수 있다.
- 변경할 메뉴 또는 옵션의 실제 매장 소속도 확인한다. 경로의 storeId만 바꿔 다른 매장 항목을 수정할 수 없다.

## MS-12 관리용 메뉴 목록

`GET /api/v1/staff/stores/{storeId}/menus`

Bearer 인증이 필요하다. 성공은 200이며 공통 응답의 `data`는 아래 배열이다.

```json
[
  {
    "menuId": 1,
    "name": "카페라떼",
    "status": "ACTIVE",
    "soldOut": false,
    "optionGroups": [
      {
        "optionGroupId": 2,
        "name": "사이즈",
        "options": [
          {"optionItemId": 3, "name": "R", "soldOut": false}
        ]
      }
    ]
  }
]
```

- 숨김 메뉴도 포함하며 메뉴 상태와 품절 여부는 별도다. 품절 변경이 메뉴를 공개하거나 숨기지는 않는다.
- 메뉴·그룹·옵션은 각각 `sortOrder`, 동일 순서일 때 `id` 순이다. 빈 매장은 빈 배열, 옵션 없는 메뉴는 `optionGroups: []`다.
- 여러 메뉴의 그룹·옵션을 일괄 조회한다. 반환된 `menuId`·`optionItemId`를 아래 변경 API에 사용한다.

## MS-13 메뉴 품절 변경

`PATCH /api/v1/staff/stores/{storeId}/menus/{menuId}/sold-out`

```json
{"soldOut": true}
```

200 응답의 data:

```json
{"menuId": 1, "soldOut": true}
```

## MS-14 옵션 품절 변경

`PATCH /api/v1/staff/stores/{storeId}/option-items/{optionItemId}/sold-out`

요청은 MS-13과 같다. 200 응답의 data:

```json
{"optionItemId": 3, "soldOut": true}
```

두 변경 API에서 `false`를 보내면 품절을 해제한다. Boolean 값은 필수이며 누락·null·잘못된 JSON은 400이다.
같은 값으로 재요청하면 200과 현재 값을 반환한다. 항목을 잠근 뒤 변경하며 이름·가격·공개 상태·매장/그룹 소속은 변경하지 않는다.

## 오류와 주문 연동

| 상황 | HTTP·code |
| --- | --- |
| 인증 없음/만료 | 401·C002 |
| CUSTOMER·ADMIN 등 허용되지 않은 주체/역할 | 403·C003 |
| 비활성·역할/사업자 변경·다른 사업자/미배정 매장 | 403·AUTH_004 |
| 없는 매장 | 404·ST001 |
| 없는 메뉴/옵션 또는 해당 매장 소속이 아님 | 404·C004 |
| soldOut 누락/null/타입 오류·본문 누락/파싱 실패 | 400·C001 |

변경 완료 후 고객 메뉴 조회와 주문 생성·결제 확인의 기존 검증이 새 품절 상태를 읽는다.

| 주문 시점의 상태 | 기존 주문 오류 |
| --- | --- |
| 메뉴 품절 | 409·OD002 |
| 선택한 옵션 품절 | 400·OD003 |

개발용 가짜 결제 확인도 품절을 다시 검사한다. 차단된 주문에는 결제 승인·픽업번호·접수 이력이 남지 않으며, 품절 해제 후 기존 주문의 확인을 다시 시도할 수 있다.
실제 PG 결제 완료 후 접수할 수 없는 주문의 보상 환불은 PR #21의 별도 기능이다. 실제 KG이니시스·앱 통합 검증은 아직 남아 있다.
